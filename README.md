# 灰度配置发布与回滚演练工具

这是一个在浏览器中运行的配置发布演练项目。它不是静态表格演示：规则匹配、百分比分桶、版本快照、发布阶段、并发冲突和回滚都由 TypeScript 核心逻辑实际执行，并有自动化测试覆盖。

## 启动方式

要求 Node.js 18 或更高版本。

```powershell
npm install
npm run dev
```

启动后打开终端中显示的地址，默认是：

```text
http://127.0.0.1:5173/
```

生产构建：

```powershell
npm run build
npm run preview
```

## 测试

```powershell
npm test
```

当前测试覆盖：

- 多条规则同时满足时的优先级判断和逐规则解释。
- 按比例灰度的稳定哈希分桶、重复访问稳定性和扩大范围后的命中集合。
- 草稿版本生成、版本字段差异比较、回滚生成新版本且保留历史。
- 两个窗口基于旧修订号提交时产生冲突，且不会覆盖新版本。
- 无规则、条件不匹配和草稿阶段返回默认配置。
- 紧急发布原因校验与记录。

## 核心规则

### 条件与优先级

每条规则可以配置：

- 用户编号，多个编号用逗号分隔。
- 地区，例如上海、北京、广州。
- 设备类型：`ios`、`android`、`web`。
- 用户标签，例如内测、高价值、新用户。
- 命中后的配置值。
- 规则自身的开放比例。

启用规则的优先级数字不能重复，数字越小越先判断。命中第一条满足条件且通过发布阶段限制的规则后立即停止；没有命中时返回默认配置。

### 稳定比例

灰度阶段使用 `FNV-1a(配置ID + 规则ID + 用户编号) % 100` 得到 0 到 99 的固定桶。只要配置 ID、规则 ID 和用户编号不变，同一用户每次访问都会得到同一个桶，因此不会在新旧配置之间闪烁。

实际比例取“当前发布阶段比例”和“规则自身比例”的较小值。例如阶段为 10%，规则自身为 50%，最终只开放 10%。

### 发布阶段

标准路径为：

```text
草稿 → 测试中 → 灰度发布 → 全部发布
```

- 草稿：规则保存为新版本，但不影响当前线上请求。
- 测试中：只有规则用户编号中明确列出的测试用户可以命中。
- 灰度发布：按稳定分桶和当前比例命中，扩大前会显示受影响用户。
- 全部发布：匹配规则的用户全部命中。
- 已回滚：当前请求读取回滚生成的新版本，历史版本仍保留。

不能直接从草稿跳到灰度或全量。若确实需要跳过阶段，只能使用“紧急发布”，并且必须填写至少 5 个字的原因；原因和时间会写入版本与操作记录。

## 内置演示流程

页面首次打开会自动载入“支付页面新版”和 10 名演示用户。推荐按以下步骤演练：

1. 在“发布流程”中点击“发布到测试”。
2. 打开“结果预览”，选择内部测试账号 `U1001`，可看到命中内部规则及完整判断过程。
3. 选择 `U1002`，可看到上海高价值用户规则；选择其他未列入测试白名单的用户会返回旧版支付页面。
4. 回到发布页，将灰度比例设为 `10`，点击“开始 10% 灰度”，页面会列出实际将命中的演示用户。
5. 在结果预览中反复切换用户；同一用户多次访问结果稳定，步骤中显示固定桶编号。
6. 将比例改为 `50`，先查看影响范围，再点击“扩大到 50%”。
7. 如果认为新版本异常，在“回滚到稳定历史版本”中选择旧版本执行回滚。
8. 再次预览用户，结果会读取回滚生成的新版本；“版本记录”和“操作记录”中的所有历史仍存在。

也可以点击“清空并重新开始演示”恢复初始演示数据。

## 版本与回滚

- 每次规则修改都会生成新的草稿版本，不会原地覆盖当前线上版本。
- 进入测试、灰度或全量会让对应版本成为当前生效版本。
- “版本记录”支持比较任意两个版本的默认值、规则、优先级、条件、配置值和规则比例。
- 回滚不是删除新版本后把旧版本改号，而是复制目标稳定版本的内容和发布规则生成一个新的版本号。
- 页面会显示当前版本和上一版本；操作记录包含回滚前版本、目标历史版本和回滚后版本。

## 并发冲突演练

1. 点击“编辑当前配置规则”并保持表单在页面中。
2. 点击顶部“模拟另一个窗口修改”，系统会用另一份数据基于最新修订号先提交。
3. 在旧表单中修改内容并保存，会收到版本冲突提示。
4. 可以选择：
   - 重新读取：放弃旧表单并查看最新数据。
   - 放弃修改：关闭本地编辑。
   - 基于最新版本继续修改：读取最新配置后重新编辑。

冲突不会静默覆盖，处理结果也会写入操作记录。真实浏览器中打开两个标签页或窗口并分别保存，也会触发同样的 `storage` 并发检测。

## 数据持久化

所有配置、用户、版本和操作记录保存在浏览器 `localStorage` 的 `gray-release-drill-data-v1` 键中。刷新页面不会丢失数据；清空浏览器站点数据或点击“清空并重新开始演示”可重新开始。
