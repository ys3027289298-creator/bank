# 灰度配置发布与回滚演练台（Gray Release Lab）

一个在浏览器中真实运行的灰度发布演练工具：配置不是静态表格，每一次规则判断、版本生成、
发布阶段流转、比例放量、回滚和并发冲突都由真实引擎计算，数据持久化在 `localStorage`，刷新不丢失。

## 启动方式

```bash
npm install
npm run dev
```

启动后在浏览器打开终端输出的地址（默认 http://127.0.0.1:5173 ，端口被占用时自动顺延）。

生产构建与本地预览：

```bash
npm run build
npm run preview
```

运行测试：

```bash
npm test
```

## 推荐演示流程（内置真实演示数据）

打开首页点击「▶ 直接体验演示场景」，进入「支付页面新版收银台」（v2 草稿，已配好 4 条规则、10 个演示用户）：

1. 「规则编辑与实时预览」：切换不同演示用户，查看逐维度条件判断、稳定桶号、比例放行说明。
2. 「发布控制台」：① 开始测试 → ② 以 10% 开始灰度；右侧**影响面预测**实时列出哪些用户将看到新配置。
3. 「结果预览」：`U1001`（白名单，100% 定向不受灰度上限限制）、`U1002`（北京 VIP）在 10% 灰度即命中；
   `U1004/U1010`（新用户，10% 规则）、`U1003/U1005` 等按稳定哈希桶号决定；同一用户多次查询结果恒定。
4. 回到「发布控制台」把范围扩大到 **50%**（比例必须递增），再对比预览结果变化。
5. 「版本记录与回滚」：选择测试阶段的稳定版本「回滚到此版本」→ 生成新版本，状态变已回滚，
   所有新访问立即使用回滚配置（结果预览中全部回到旧配置），历史版本仍在，可查看 v 之间的字段级 diff。
6. 「双窗口冲突演练」：打开两个窗口 → 窗口 A 先提交 → 窗口 B 再提交会被乐观锁拦截，
   可选：重新读取 / 放弃修改 / 基于最新版本继续修改，三种处理全部写入操作记录。
7. 首页提供「重置为演示数据」和「清空全部数据重新开始」。

## 核心实现（都是真的）

- **规则引擎** `src/engine/rules.ts`
  - 条件维度：用户编号、地区、设备类型、用户标签；条件内为“或”，维度之间为“与”，空维度表示不限。
  - 规则按 `priority` 升序逐条判断，第一条“条件 + 比例”均通过的规则生效，其余不再判断；每条规则都留下完整判断轨迹。
  - 按比例放量使用 FNV-1a 稳定哈希（`src/engine/hash.ts`），桶号 = `hash(configId:ruleId:userId) % 100`，
    同一用户永远落到同一桶，保证重复访问结果稳定。
  - 比例 < 100% 的规则取「规则比例」与「全局灰度上限」的较小值；比例 = 100% 的定向规则（白名单/VIP）不受灰度上限压缩。
  - 状态门禁：草稿一律下发默认配置；测试中命中条件即放行（不放量）；灰度按比例；全量全部放行；已回滚全部关闭。
- **发布状态机** `src/state/store.ts`：`draft → testing → gray → full`，不可跳步；
  只有填写原因的「紧急发布」允许跳阶段；每次流转都生成新版本、记录时间与原因；扩大灰度比例必须递增。
- **版本与回滚**：每次编辑/发布生成递增版本，快照不可变；`src/engine/diff.ts` 做字段级版本对比；
  回滚目标必须是曾经真正生效的稳定版本；回滚产生新版本（保留全部历史），新访问立即按回滚版本判断；
  回滚后可基于任意稳定版本「新建修订」重新走完整发布流程。
- **乐观锁冲突**：编辑时携带页面所基于的 `baseVersion`，与当前版本不一致即拒绝（`conflict_blocked`），
  绝不会静默覆盖；用户显式选择“基于最新版本继续”才生成新版本（`conflict_forced`）。
- **操作记录**：创建、修改、各发布阶段、扩大范围、紧急发布、回滚、冲突拦截/继续、重置均记录
  操作类型、配置名、版本变化、时间、结果与原因，回滚不删除任何记录。

## 项目结构

```
index.html
src/
  main.tsx / App.tsx          # 入口与路由（首页 / 配置详情）
  styles.css
  engine/
    types.ts                  # 全部领域模型
    hash.ts                   # 稳定哈希分桶
    rules.ts                  # 规则引擎：条件/优先级/比例/状态门禁/影响面预测
    diff.ts                   # 版本快照字段级对比
    rules.test.ts             # 规则与比例测试
  state/
    store.ts                  # 状态机：创建/编辑/乐观锁/发布/回滚/审计 + localStorage
    demoData.ts               # 内置演示项目、规则与 10 个演示用户
    useStore.ts               # React 绑定与全局提示
    store.test.ts             # 版本/发布/回滚/冲突测试
  components/                 # 规则编辑器、预览面板、发布台、版本面板、冲突演练、操作记录
  pages/                      # 首页、配置详情页
```

## 测试覆盖（19 个用例，含一个 React 端到端冒烟）

- 规则优先级排序、高优先级比例未命中时降级到后续规则、停用规则不生效、维度逐条件判断。
- 比例放量约 10% / 50% 的分布正确性、全局灰度上限约束、100% 定向规则豁免、同用户重复评估稳定。
- 草稿/无规则时返回默认配置、影响面预测。
- 版本递增生成、版本 diff、表单校验（空名称、重复优先级、比例越界）。
- 发布门禁（禁止跳步、紧急发布原因必填、扩量比例递增）。
- 回滚到稳定版本、禁止回滚到草稿、回滚后新访问使用回滚配置、历史保留。
- 双窗口并发修改的乐观锁拦截、冲突后基于最新版本继续。
- UI 端到端冒烟：实际挂载页面，从开始页进入演示项目，真实点击完成 测试 → 10% 灰度 →
  扩大 50% → 回滚，并断言操作记录与 localStorage 持久化。
